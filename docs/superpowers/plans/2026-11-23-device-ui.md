# Device Pages and Device Data Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A C# device keeps a page of cards in the HassSharp panel and data that survives recompiles and restarts.

**Architecture:** Device code builds lists of cards through `SharpComponent.Ui`; the definition's host keeps the
page in memory and runs button handlers. Device code keeps values through `SharpComponent.Data` and `Shared(name)`,
backed by directories under `.storage/hass_sharp/data/`. One admin-only websocket command, `hass_sharp/device_ui`,
carries pages, images, button presses, counts and store management to a new Device tab in the entity definition
editor. The panel polls; nothing is pushed.

**Tech Stack:** C# on .NET 11 (`custom_components/hass_sharp/HassSharp/`), Python (Home Assistant integration),
SolidJS + TanStack Query + vitest (`custom_components/hass_sharp/frontend/`).

**Spec:** `docs/superpowers/specs/2026-11-23-device-ui-design.md`. Read it before any task; where this plan and
the spec disagree, the spec wins.

## Global Constraints

- Paths in this plan are relative to the repository root unless they start with `HassSharp/` or `frontend/`, which
  are under `custom_components/hass_sharp/`.
- Read `AGENTS.md` first. Its rules bind every task, in particular:
  - A lock in new C# is a `System.Threading.Lock` field taken with `lock`; never an `object`, `this` or a
    collection; a `lock` never spans an `await` (use `SemaphoreSlim` there).
  - `tests/Runtime/` is compiled by hass-sharp-vision under the assembly name `HassSharp.RuntimeTests`: add
    helpers freely, never rename an existing helper or the `InternalsVisibleTo`.
- No new NuGet, npm or Python dependency.
- Only JSON text and bytes cross between load contexts and into Python. No user-assembly object is held by anything
  that outlives its definition's host.
- Device pages, images and stored data reach admins only: no MCP tool, no HTTP route, no log line that contains a
  stored value, a field value or image bytes.
- Every exception message a user can see is a plain sentence that names no parameter, in the style of
  `HassSharp/Devices/SharpFiles.cs`.
- Limits, exact values: 20 lists per page; 200 cards per list; 8 fields and 4 actions per card; an image at most
  1 MiB (1,048,576 bytes) as JPEG; a stored value at most 8 MiB; a store at most 512 MiB; an action handler has
  30 seconds; the Device tab polls `read` every 2 seconds; counts are polled every 10 seconds.
- Storage paths, exact: `.storage/hass_sharp/data/devices/<definitionId>/<nodeKey>/` and
  `.storage/hass_sharp/data/shared/<name>/`.
- `Ui`, `Data` and `Shared` work from `Start()` on and throw `InvalidOperationException` before it.
- Tests come first (write the failing test, see it fail, implement, see it pass). Suites:
  - `dotnet run --project tests/Runtime --disable-build-servers -- <suite flag>` for one suite, without a flag for
    all. Run the task's suites while working and the whole runtime suite once before reporting.
  - `python3 -m unittest discover -s tests/python`
  - `(cd custom_components/hass_sharp/frontend && bun run test)`
- Commits: one plain sentence that says what the code now does, no prefix, no trailer (see `git log`). Never push.
- Anything a tool or agent reads as a diff uses `git --no-pager diff --no-ext-diff`.
- Never use the `mcp__hass__*` tools; they reach a production Home Assistant.
- A new runtime suite is a static class with `[RuntimeSuite("--flag", Order = N)]` (`tests/Runtime/RuntimeSuiteAttribute.cs`);
  use `Order = 41` to `45` for the suites this plan adds, and the helpers in `tests/Runtime/EntityTestHome.cs`.

## Review Focus

Each line names a condition the spec implies and the task whose tests pin it.

1. A device that redraws a list on every frame, each time with new images: memory must not grow, and only the
   current page's images are kept (Task 4).
2. A value file that is corrupt or was edited by hand: `Get<T>` throws a plain sentence naming the key, other keys
   still read, and the device can overwrite it (Task 2).
3. A store or key name built from outside input, such as `../x`, an absolute path or an empty segment: refused
   before the disk is touched (Task 2).
4. Two browser tabs pressing the same button at once: the handler runs once per press in turn, and the second
   press is answered `changed` when the first removed the card (Task 5).
5. Text from a device that looks like markup (`<script>`, `<img onerror>`), very long text and non-Latin text: drawn
   as text, wrapped, never interpreted (Task 8).

### Task 2: The data stores (`SharpData`, `DataStores`)

Standalone: no host yet. Task 3 wires it into components.

**Files:**
- Create: `HassSharp/Devices/SharpData.cs` (the public handle), `HassSharp/Devices/DataStores.cs` (the stores of
  one HassSharp instance)
- Test: Create `tests/Runtime/SharpDataTests.cs` (suite `--sharp-data`, `Order = 41`)

**Interfaces:**
- Produces, public (`namespace HassSharp`):

```csharp
public sealed class SharpData
{
    public T? Get<T>(string key);                       // default when the key has no value
    public void Set<T>(string key, T value);
    public byte[]? GetBytes(string key);
    public void SetBytes(string key, byte[] value);
    public bool Remove(string key);                     // false when it had no value
    public IReadOnlyList<string> Keys(string prefix = "");   // ordinal order
    public T Update<T>(string key, Func<T?, T> change); // read, change and write as one step; returns what it wrote
    public IDisposable Changed(Func<Task> action);
    public void Clear();
}
```

- Produces, internal:

```csharp
internal sealed record DataUser(string DefinitionId, string NodeKey, Func<Func<Task>, Task> Run);
internal sealed record SharedStoreInfo(string Name, long Bytes, IReadOnlyList<string> Users);   // Users: definition ids, ordinal order, distinct

internal sealed class DataStores(string root)
{
    internal static long ValueLimit { get; set; }   // 8 MiB; settable for tests
    internal static long StoreLimit { get; set; }   // 512 MiB; settable for tests
    internal SharpData OpenDevice(DataUser user);                 // devices/<DefinitionId>/<NodeKey>/
    internal SharpData OpenShared(string name, DataUser user);    // shared/<name>/
    internal void Close(DataUser user);                            // every handle that user opened; they throw ObjectDisposedException after
    internal void DeleteDevice(string definitionId);               // the definition's whole directory
    internal void PruneDevice(string definitionId, IReadOnlySet<string> nodeKeys);   // deletes its node directories not listed
    internal IReadOnlyDictionary<string, IReadOnlyList<string>> Stored();   // definition id → node keys that hold data, from memory
    internal IReadOnlyList<SharedStoreInfo> Shared();
    internal bool DeleteShared(string name);                       // false, deleting nothing, while a handle on it is open
}
```

**Behaviour the tests pin:**
- **Names.** A key is 1 to 200 characters of segments joined by `/`, each segment matching
  `[a-z0-9][a-z0-9_.-]*`. A shared name matches `^[a-z0-9][a-z0-9_.-]{0,63}$`. Anything else is an
  `ArgumentException` before the disk is touched.
- **Values.** `Set<T>` stores JSON; `SetBytes` stores bytes. A key holds one or the other: reading it the other way
  throws `InvalidOperationException` naming the key. A JSON value that cannot be read as `T` throws
  `InvalidDataException` naming the key.
- **Writes** are complete on disk before the call returns: a temporary file in the same directory, flushed to
  disk, then renamed into place, as `SharpFiles.Fetch` does. A write that fails leaves the old value and no
  temporary file. Temporary files left by a crash are removed when the store opens and are never listed as keys.
- **Limits.** A value over `ValueLimit`, or a write that would take the store over `StoreLimit`, throws
  `InvalidOperationException` and writes nothing.
- **One store, many handles.** Every operation on a store is atomic against every other handle's. `Update` holds
  the store for its read, the caller's `change` and its write.
- **`Changed`.** After a handle writes, removes or clears, the `Changed` actions of every *other* open handle on
  that store run, each through its user's `Run`, one at a time per subscription, coalesced (several writes while
  one runs cause one more run, not one per write). The writer's own subscriptions do not run. Disposing the
  returned handle, or `Close`, ends it.
- **Serialising.** `Get<T>`, `Set<T>` and `Update<T>` use one `JsonSerializerOptions` instance per `SharpData`
  handle, never a static or shared one, so the serialiser's type cache dies with the handle.
- **`Stored()`** is kept in memory: read from the directories once when `DataStores` is made, then updated by
  writes, clears, deletes and prunes.

- [ ] **Step 1: Write the failing tests** in `SharpDataTests.cs`, each on a fresh temporary root:
  - `ValuesComeBack`: `Set("people/ivan", record)`, `SetBytes("crops/1", bytes)`; a second `DataStores` on the same
    root (a restart) reads both equal; `Keys()` is `["crops/1", "people/ivan"]`; `Keys("people/")` is the one.
  - `RemoveAndClear`: `Remove` answers true then false; `Clear` leaves no keys and no files.
  - `BadNamesAreRefused`: keys `""`, `"../x"`, `"/x"`, `"a//b"`, `"A"`, `".x"`, a 201-character key; shared names
    `"../x"`, `""`, `"X"`, 65 characters: each `ArgumentException`, and the root holds no new file or directory.
  - `AKeyHoldsOneKind`: `GetBytes` on a JSON key and `Get<int>` on a bytes key each throw
    `InvalidOperationException` whose message contains the key.
  - `ACorruptValueIsNamed` (Review Focus 2): write garbage into a value's file by hand; `Get<Person>` throws
    `InvalidDataException` containing the key; another key still reads; `Set` on the corrupt key then reads back.
  - `AFailedWriteKeepsTheOldValue`: with `ValueLimit = 16`, `Set` of a long string throws; the old value reads; no
    temporary file is in the directory.
  - `TheStoreLimitHolds`: with `StoreLimit = 64`, a second write that passes it throws; replacing a value with a

  - `LeftoversAreRemoved`: a temporary file put in the directory by hand is gone after the store opens and was

**Behaviour:**
- The node of a component is its C# node (`DefinitionHost.Node`, `nodes`): a C# entity's own, a C# device's, or
  the device's for an entity the device added. `Data` is that node's store; the same handle is returned on each
  use within one host.
- Before the host runs `Start()` on that component (constructor, `Setup()`), both throw
  `InvalidOperationException`: "`<Class>` is not running yet: use Data from Start or later, not from Setup or the
  constructor." (and "Shared" likewise). They work inside `Start()` itself, in timers, tracks, commands and
  `Stop()`.
- A `Changed` action runs as a track callback does: off the writer's thread, stopping waits for it, its failure is
  logged for the definition and not rethrown.
- When the host has stopped (after the last `Stop()`), it closes its handles (`DataStores.Close`).
- When a host starts (`StartAsync`, after the revision it replaces has stopped), it prunes its definition's device
  stores to the keys of its C# nodes (`PruneDevice`). So data of a node removed from a saved definition is deleted
  when the definition next starts, and never while the old revision still runs.
- When a definition is deleted (`EntityRequest` `delete`), its device data is deleted (`DeleteDevice`) after its
  host has stopped.
- Turning a definition off, a failed compile and a failed start delete nothing.

**Interfaces:**
- Produces, public (`namespace HassSharp`):

```csharp
public sealed class SharpUi
{
    public void List(string id, string title, IEnumerable<UiCard> cards, bool attention = false, string? empty = null);

}

public sealed class UiCard(string id)
{
    public UiCard Image(SharpImage image);  // encoded to JPEG now
    public UiCard Image(byte[] jpeg);
    public UiCard Text(string title, string? detail = null);
    public UiCard Field(string key, string label, string? value = null, bool required = false, IEnumerable<string>? suggestions = null);
    public UiCard Select(string key, string label, IEnumerable<string> options, string? value = null, bool required = false);
    public UiCard Number(string key, string label, double? value = null, double minimum = double.NaN, double maximum = double.NaN, bool required = false);

public sealed class UiValues

    public double? Number(string key);
    public bool Toggle(string key);
}

public sealed class UiRefusal(string message) : Exception(message);
```

- Produces, internal:

```csharp
internal sealed class DevicePage(string nodeKey, string title)
{
    internal SharpUi Ui { get; }
    internal bool Used { get; }                 // a list was added at least once
    internal int Attention { get; }             // cards in lists added with attention: true
    internal event Action? Changed;             // after each List or Remove that changed the page
    internal JsonObject Snapshot();             // the page data of the spec, without "revision"
    internal byte[]? Image(string hash);
    internal UiPress? Find(string list, string card, string action);
    internal void Close();                      // drops lists, handlers and images; List and Remove throw ObjectDisposedException after
}

/// The action a press named, with what the host needs to check and run it.
internal sealed record UiPress(Func<UiValues, Task> Run)
{
    /// The values as the handler gets them; throws UiRefusal with a plain sentence for a missing required field,
    /// a number outside its range, an option the select does not have, or a value of the wrong kind.
    internal UiValues Values(JsonObject sent);
}
```

**Behaviour the tests pin:**
- **Ids.** A list id and a card id match `^[A-Za-z0-9][A-Za-z0-9_.:-]{0,63}$`; a field key matches
  `^[a-z][a-z0-9_]{0,39}$`. An action's id is its label lower-cased with every run of other characters replaced
  by `_` and trimmed of `_`; two actions of one card with the same id, two fields with the same key and two cards
  with the same id in one list are refused.
- **Text.** A title, detail, label, option, suggestion, value, confirm and empty text is at most 500 characters.
- **Validation happens in `SharpUi.List`**, which throws `ArgumentException` (a plain sentence) and leaves the
  page as it was: a bad id, a duplicate, text too long, more than 200 cards, more than 8 fields or 4 actions on a
  card, a 21st list, an image over 1 MiB, image bytes that do not start with the JPEG marker `FF D8`, a `Select`
  with no options or a value not among them, a `Number` whose value is outside its range.
- **Lists** keep the order of their first `List` call; replacing a list keeps its place.
- **Snapshot**, exact shape:

```
{ "nodeKey", "title", "attention": <int>,
  "lists": [ { "id", "title", "attention": <bool>, "empty": <string|null>,
    "cards": [ { "id", "image": "<sha256 hex>"|null, "title": <string|null>, "detail": <string|null>,
      "fields": [ { "key", "label", "type": "text"|"select"|"number"|"toggle", "value",
                    "options"?, "suggestions"?, "minimum"?, "maximum"?, "required": <bool> } ],
      "actions": [ { "id", "label", "style": "default"|"primary"|"danger", "confirm": <string|null> } ] } ] } ] }
```

- **Images** are kept by the SHA-256 of their JPEG bytes (lower-case hex) and only while a card of the current
  page uses them.
- `List`, `Remove`, `Snapshot`, `Image` and `Find` are safe from any thread.

**Files:**

**Interfaces:**

- Produces:
  - `SharpComponent`: `protected SharpUi Ui { get; }`; `IComponentHost`: `SharpUi Ui(SharpComponent component)`.

```csharp
internal static TimeSpan UiActionTimeout { get; set; }      // 30 s; settable for tests
internal string UiRevision { get; }                          // changes with every change of any page, and differs between hosts
internal IReadOnlyList<JsonObject> UiPages();                // the snapshots of the nodes whose page is Used, in node order
```

**Behaviour:**
- One `DevicePage` per C# node, titled as the host names the node (`Called(node)`); a device and the entities it
  added get the same `SharpUi`. `Ui` throws before `Start()` exactly as `Data` does (Task 3), with "use Ui from
  Start or later".
- `UiAct`:
  - The definition must be running (as `Command` checks, under `gate`), else `InvalidOperationException`
    "The entity definition is not running".
  - `Find` on the current page; null → `changed`. `Values` throwing `UiRefusal` → `refused` with its message.
  - Presses of one page run one at a time, in the order they arrived, off the caller's thread. The lookup happens
